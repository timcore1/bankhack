Изолированное учебное приложение интернет-банка для отработки навыков анализа безопасности веб-приложений.

## Стек
- **Database:** PostgreSQL 16
- **Backend:** Python 3.12, FastAPI, SQLAlchemy, Pydantic, PyJWT, Jinja2
- **Frontend:** React 18, Vite, Tailwind CSS, Lucide Icons, Nginx (reverse proxy `/api` -> `backend:8000`)

## Быстрый старт

```bash
docker compose up --build -d
```

После запуска приложение будет доступно по адресу: `http://localhost:3000`.

## Предустановленные пользователи (`init_db.py`)

| ID | Логин | Пароль | Роль | Баланс |
| --- | --- | --- | --- | --- |
| 1 | `user1` | `user1pass` | `user` | `100.00` |
| 2 | `vip_client` | `vippass123` | `vip` | `50000.00` |
| 3 | `admin` | `adminpass123` | `admin` | `100000.00` |

ID назначаются автоматически в порядке создания в `backend/app/init_db.py`, поэтому `vip_client` получает ID 2, а `admin` — ID 3.

## Краткое описание CTF-этапов

> Подробные решения, payload'ы и флаги — в отдельном файле [`WRITEUP.md`](WRITEUP.md). Ниже — только описание уязвимостей, без спойлеров.

### Этап 1 — IDOR (Insecure Direct Object Reference)
`GET /api/v1/transactions/{user_id}` отдаёт историю транзакций по числовому идентификатору, но не проверяет, что `user_id` принадлежит текущему пользователю. Перебирая чужие ID, можно прочитать операции другого клиента и найти служебные данные в комментарии к переводу.

### Этап 2 — Race Condition (TOCTOU)
`POST /api/v1/transfer` выполняет проверку баланса и списание двумя отдельными запросами, а между ними есть искусственная задержка `asyncio.sleep(0.2)`. Блокировка строки (`SELECT ... FOR UPDATE`) не используется, поэтому при параллельной отправке запросов на перевод проверка баланса успевает пройти несколько раз до первого списания.

### Этап 3 — Слабый JWT, SQL Injection и SSTI в админ-панели
1. **Слабый секрет JWT.** Токены подписываются алгоритмом HS256 паролем из словаря. Секрет можно подобрать по перехваченному токену, после чего переподписать его с произвольной ролью. Сама проверка роли на бэкенде доверяет клейму `role` из JWT, а не значению в базе данных.
2. **Скрытая админ-панель.** На фронтенде есть страница `/admin`, ссылка на неё в кабинете появляется только при `role == "admin"` в токене. Панель позволяет искать клиентов и формировать выписки.
3. **SQL Injection.** `POST /api/admin/export` собирает запрос конкатенацией строк вместо параметризации.
4. **SSTI.** Поле «шаблон комментария» рендерится через Jinja2 без песочницы и без автоэкранирования, что позволяет выполнить произвольный код в контейнере бэкенда.
